# 📄 文档 1：插件整体架构与技术规格说明书 (PRD/Arch)

> **适用对象：** AI Agent (Antigravity) 核心上下文注入、人类程序员技术审查

## 1. 项目愿景与核心目标

* **产品名称：** EtymoRead (暂定：词根词缀智能阅读助手)
* **核心痛点：** 英文泛读的最大障碍是词汇量，而死记硬背效率极低。通过“词根词缀”的逻辑拆解是建立语境、指数级扩充词汇的最佳路径。
* **产品定位：** 一款**完全免费、纯粹简洁、去中心化**的 Chrome 机制增强型阅读插件。
* **核心承诺：** 0 服务器成本、0 隐私泄露、完全由用户本地算力驱动。

## 2. 技术栈架构 (Tech Stack)

* **扩展框架：** `WXT` (基于 Vite 的现代跨浏览器扩展开发框架，提供极佳的 TS 支持和极其干净的目录结构)
* **前端视图：** `React 18+` + `TypeScript` (保证组件化和类型安全)
* **样式表现：** `Tailwind CSS` 或纯 CSS (保持极致轻量，避免卡顿)
* **PDF 渲染引擎：** `PDF.js` (Mozilla 开源，用于拦截并自主渲染 PDF，将其转化为可被注入 Content Script 的标准 DOM 树)
* **核心数据集：** 本地静态离线包 (`affixes.ts` 200前/后缀，`wordRoots.ts` 400核心词根)

## 3. 混合动力核心算法方案 (Hybrid Tiered Architecture)

为了完美兼顾“网页/PDF 渲染性能”与“未知词汇的拆解精准度”，插件采用双引擎分级联动机制：

```
[页面加载 / PDF 文本层渲染渲染完成]
       │
       ▼
【第一层：方案 A-1 静态高亮引擎】
 核心技术：基于本地内存中 600 个核心词根词缀，利用“词干提取(Stemming)/正则滑动窗口”算法。
 运行表现：毫秒级全自动化扫描。不发起任何网络请求。
 交互行为：
   ├─► 发现符合构词规律的词 ──► 自动加上淡淡的下划线
   └─► 用户 Hover ──► 瞬间弹出本地缓存数据拼接的 Tooltip（零延迟）
       │
       ▼
【第二层：方案 B 动态探针引擎（优雅升级机制）】
 核心技术：Google Chrome 130+ 底层原生内置的 `window.ai` (Gemini Nano 本地大模型)。
 激活触发：用户双击（dblclick）未被静态高亮的任何长尾/冷门生词。
 运行表现：
   ├─► 初始化检查：若检测到硬件/浏览器支持，提示用户手动开启，默认关闭。
   └─► 运行过程：算力 100% 消耗在用户本地本地 GPU/CPU，开发者承担 $0 服务器费用。

```

## 4. PDF 接管机制 (PDF Takeover Flow)

1. **权限声明：** 在 `manifest.json` 中配置 `"permissions": ["webRequest", "webRequestBlocking", "storage"]` 并允许用户开启“允许访问文件 URL (file://)”。
2. **重定向：** 拦截所有 `content_type` 为 `application/pdf` 的请求，或者匹配扩展名为 `.pdf` 的 URL。
3. **渲染：** 将请求重定向到 WXT 的自定义页面（例如 `entrypoints/pdf-viewer.html`），该页面利用 `PDF.js` 将 PDF 文件渲染出来，并输出标准的 HTML `textLayer`。
4. **同构：** 我们的 Content Script 会自动作用于这个自定义的阅读器页面，从而让 PDF 像普通网页一样获得完整的自动高亮与双击 AI 拆解能力。
